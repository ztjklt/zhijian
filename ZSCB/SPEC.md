## 1. 产品定位

《纸间》（历史名称《指尖》《纸上城堡》）是一款 2D 侧视、实时手绘造物的多人沙盒。玩家进入同一张向左右延伸的纸面，控制火柴人，边移动边画出物体、建筑和武器，利用真实物理自由搭建、互动与交手。

用户于2026-10-25最新明确名称为「纸间」，覆盖此前「指尖」的命名要求。当前界面与公开文案统一为纸间；历史设计、固定包、域名、存档文件和存储命名空间保留原名，避免名称修正导致身份或作品丢失。

首版面向朋友之间的私人双人房间，支持异地互联网联机。玩家可以合作，也可以互相伤害；战斗始终属于同一个沙盒世界，不需要进入独立战斗模式，不强制阵营、回合或胜负结算。以后逐步扩展房间人数。

核心体验：**画出东西 → 让它进入世界 → 移动、搭建、使用或破坏 → 保存作品，继续创造。**

## 4. 世界、角色与美术

- 保留纸张、手绘线条和现有火柴人风格；不因联机改成另一套角色美术。
- 纸面可向左右探索，草稿纸／课本纸张及已有地图视觉保持兼容。一次房间中，纸张与物理世界由所有玩家共享。
- 每人控制一个角色，具有独立位置、朝向、动作、生命、武器、草稿、背包、快捷栏和镜头。
- 用姓名、点缀颜色与血条区分玩家。每台设备跟随自己的角色；两人可以分开探索，不强制共享镜头。
- 世界持续运行。打开背包、输入文字、切换绘画工具或绘画不会暂停别人及世界物理。
- 多人首版不启用角色之间的刚体推挤；武器命中仍能互相伤害，角色仍与地面和造物正常互动。

## 6. 造物、物理与破坏

- 建筑和自由造物默认是动态刚体，会下坠、碰撞、旋转、滚动或倾倒，保留轮廓对重心和落地姿态的影响。

- 用户于2026-10-25再次明确：玩家用笔画出并生成的建筑同样属于可攻击破坏的造物，普通单人模式与双人模式都必须支持；双人中自己和另一人的建筑均可被攻击，受损及最终破坏由服务器裁决并同步双方。不能仅让地图预置建筑可破坏，或仅通过“4 移动／拆除”实现删除。

## 11. Railway 技术路线建议

### 方案选择

| 方案 | 取舍 |
| --- | --- |
| Railway + Godot 无窗口权威服务器 + WSS | 推荐。复用现有 Godot 物理，适配 Railway 文档明确支持的 WebSocket 入口，减少玩家家庭网络配置。TCP 丢包可能增加延迟，需要真实手感验收。 |
| 玩家电脑托管 + 穿透／中继 | 增加玩家网络差异及中继接入工作，首版不采用。 |
| 独立 UDP 游戏服务器，Railway 仅管房间 | 可以作为后续低延迟方案，但涉及另一套托管环境，当前不默认引入。 |

- 游戏服务器继续使用 Godot 的同一套绘画规则、碰撞形状与伤害计算，不改写成另一种语言的近似物理。

## 13. 首版范围与后续方向

2026-10-26用户授权按以下顺序渐进改进：先稳定绘画与联机手感，再增加可用绘画解决的地图小事件、结构连接与搭建用途、武器设计试验、双人共同创造及完整的新手小成功。后续具体事件／关节／合作规则仍需在对应阶段按实际实现细化；本次授权不把前述建议的所有例子当作已实现功能，不自动授权云部署。

第一阶段的本人拉弓与Q切弓可以即时呈现动作意图，跟踪上一把武器的同源冷却；不能因此由客户端放箭、扣墨或决定命中。个人界面、失焦、受伤、换装备、死亡、断线和世界切换及时结束本人蓄力姿态，迟到帧不能将它重新激活。服务器攻击结果可附带`attack_started`，区分已接收但因冷却等条件未实际开始的请求；这一可选字段沿用协议6。开发候选与公网r7分别说明；不同网络两台设备实玩仍以实际证据为准。

第二阶段细化为可选的“磨坊试桥”：中世纪磨坊渡口附近，玩家主动布置两端试桥台，先画桥或组合支撑，再投放真实刚体小货车。平台仅在安全空位布置，不自动插入旧作品；不拆掉现有河桥。货车仅在实际接触时受有界水平驱动力，不沿路径移动、不自动飞越缺口；抵达右台并真实接触、低速稳定0.5秒才送达。无桥或结构失稳会掉落，可重试且保留所有玩家搭建。试桥夹具只属于这一可选事件，不收入图纸、不发放资源，不扩展当前墨水经济。

单人从地图／本版体验进入事件，联机沿地图走近后双方可共同布置、绘画和投放。事件、尝试次数、完成记录和运行中的货物保存到对应世界；旧作品缺少字段时为未布置。联网只接受布置／投放动作，距离、生死、接触与完成由服务器判断，重复请求不重复生成。新碰撞和事件状态使用开发协议7／r9候选，与公网协议6／r7及手感协议6／r8分别记录；不因本条规范自动发布。桌面、窄横屏、竖屏及触控入口须实际验证。

第三阶段细化为“固定连接与转轴”：先分别画出实体，再从4移动／拆除的操作按钮显式切换固定连接、转轴或解除，默认仍是移动。依次点两件相邻自己部件的实际材料接缝，点间距不超过0.5米，锚点距双方现存碰撞材料最多0.25米；空洞、装饰和已切掉的材料不能作连接。每对至多一个连接、每地图最多128个，绿色记号区分固定与转轴。固定连接保持相对位置与角度，转轴允许绕锚点转动；双方保留独立真实刚体，不用冻结或逐帧写坐标模拟结构。连接不额外扣墨，部件图纸仍是单件，不把当前授权扩展成整组图纸或共同编辑权限。

连接用稳定部件键与局部锚点存入对应世界`connections`。旧档缺失字段为空，非法引用／非有限锚点／重复连接／已失去材料的锚点在载入前拒绝；地图切换保留各自结构。拆除部件或砍掉锚点会断开，解除后恢复部件间碰撞；已连接部件先解除再独立移动，防止拖动拉飞整组。连接、解除和删除的撤销须仍满足有效材料与权限；不能借撤销绕过12米范围或已有编辑锁。

联网双方只显示权威连接及刚体状态，客户端不创建关节或自行模拟搭建。服务器检查双方作者、连接点和部件均在12米内、生死与编辑锁，并沿用编号去重；建立／解除／破损引起的连接变化通过版本快照同步，迟到加入和重连一致。新物理规则使用开发协议8／r10候选，沿用r9试桥与r8手感；公网仍按r7发布事实说明。本轮仍未自动部署，不同网络双物理设备实玩仍待验收。

第四阶段细化为“武器试打与方案对照”：通过作品菜单、武器工具或本版体验打开，显式在朝向1.2／2.5／5米布置每人一个临时试靶，检查地形、造物、角色占位，拒绝时保留旧靶。试靶只作为本人攻击的测量目标，不推挤角色、物件，不发墨弹、不提供奖励，不暂停世界；朋友能看见各自试靶，不能替对方操作或上传成绩。

真实剑模扫掠、实际握点、墙遮挡及弹丸最早接触决定命中。同一挥击只记录一次，取消拉弓不记命中。显示当前方案的握点到笔迹最远距离、真实攻击冷却，以及实测命中数、最近／平均／最高伤害、最远接触距离；零命中不生成虚假测试结论。可保留一份当前实测对照，更换类型、握点或笔迹分别计数；飞行中的弹丸绑定发射时的方案，换武器不能串成绩。移靶、清空、死亡、断线和世界替换使旧一轮票据失效；记录有界为8个方案与一份对照，仅本次会话，不进入世界存档和本机图纸资料。

复制回画布只平移完整笔迹，保留多笔相对关系和填充偏好，原装备和图纸保留。已有武器草稿时拒绝覆盖，仍需3选握点→3类型→3装备才确认改稿，类型默认沿用原武器。打开个人面板隔离绘画、攻击及玩法键，关闭后正常试打，好友世界继续运行。联网布靶、成绩、保留对照与清空均由权威执行，客户端仅显示自己的结果与双方靶位；只接收动作、固定距离，不接收客户端成绩／靶坐标／他人身份。

建议依次完成：拆分玩家和世界 → 本机服务器连接两客户端 → 同步造物与物理 → 互伤／重生／权限 → 房间及存档 → Railway 实测与手感优化。

完成必须具备以下证据：

1. 两个真实客户端连接同一服务器，总玩家为 2，第三人明确被拒绝；两人移动、绘画、装备、界面和镜头互不串状态。
2. 同一实体只生成一次，物理状态收敛；相距超过原单镜头加载范围，双方仍有正常地面和物理。
3. 近战距离、方向、墙体遮挡、冷却、单次去重、互伤、死亡、保护及重生正常，另一人不中断。
4. 建筑受损与破坏一致；编辑锁释放；一人撤销不覆盖另一人，不能复活被打坏的物体。
5. 入房快照与增量正确衔接；重连凭据与权限有效；不同房间没有碰撞或广播串房。
6. 世界存档与个人图纸隔离；旧作品迁移、服务重启恢复、失败保存提示和完整快照备份通过测试，不覆盖用户真实存档。
7. 既有绘画、自动落体、复杂轮廓、握持点、触控和存档测试继续通过；桌面与窄屏实际画面验证角色、血条、入口和重生提示。
8. Railway 上实际部署并由不同网络的两台设备联机；测试约 100ms 往返延迟、带宽拥塞和连接中断，不重复生成／扣血，输入及时归零，状态最终一致。
9. LAN、本机或模拟测试不能代替异地部署证据。缺少设备、账号权限或部署授权时标记未验证，不能把整个多人首版称为完成。
