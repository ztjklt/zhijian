# 纸间网页版卡顿优化（2026-10-25）

用户明确卡顿表现为走路、镜头、绘画都不流畅。本轮继续使用固定r2／协议2与已部署权威服务器；候选包 `dist/纸间网页版-20261025-perf/`，未纳入同期协议3。先做故障测量，再做两处客户端热点修复和前后台渲染预算。

## 基线与定位

真实WebGL2浏览器的2560×1440渲染视口：封面约120fps、process约3.3ms；中世纪地图约119–120fps、process约12–14ms、physics约0.8–2ms，绘制135–325次，节点3075。移动与村庄／集市区域仍可达到测试机刷新率，因此没有声称复现用户设备上的低帧率。RTT约300–600ms与画面开销分开记录。

- UI布局假设已排除：12轮稳定面板更新只触发2次尺寸变化，邀请模态稳定，未做缺乏证据的布局重写。
- 确认热点1：toolbar.update_buttons每渲染帧把完整武器笔迹字典转成字符串，但按钮更新正文不读取该数据。5000点武器时缓存键96499字符，120轮约269ms。
- 确认热点2：每个地图状态记录都调用线性entity_by_id；300实体、60个状态帧会做2727000次扫描，约135ms。

## 修复与回归

- UI缓存只包含真实影响按钮的状态，去掉完整武器序列化：同一隔离夹具120轮约0.379ms，缓存89字符。
- 每个已接收状态帧创建一次ID字典，生命周期不跨帧或快照：同一夹具60×300实体约14.766ms，无重复线性扫描；未知ID、epoch及旧tick保护保持。
- Web前台默认最高60fps、失焦后台20fps；SceneTree和网络处理不暂停，物理规则及协议不变。
- 每秒一次的DOM性能数据仅用于本机核验，不包含凭据、玩家名字或作品内容，不发送外部服务。

新性能检查先RED（武器缓存／实体扫描／无帧预算），修复后9/9通过。完整6/6脚本通过（流程16项、房间18项、保存返回10项、身份地址恢复与客户端PASS）。实际ReadableStream下载中断恢复两项仍通过。

以上是指定微基准耗时，不能把比值换算为整体FPS倍数。独立只读审查无Critical或Important；已收窄限帧测试措辞，并纳入默认回归。

## 浏览器与发布

真实浏览器使用同一localhost origin、原浏览器身份，经既有公网WSS从「继续作品」重开原世界，生成新房间40EF2ED5通过。前台引擎计数60fps／预算60，物理约0.6–1.2ms；移动、四笔绘画和确认后objects=1，画面可见真实造物。切到临时HTML焦点按钮后报告focused=false、预算20／计数20，connected=true，last_tick持续增长（证据background及background-later.json）；重新点击游戏后focused=true、预算60／计数60，移动及绘画继续。均未暂停网络树。

帧时16.666／50ms为引擎delta样本，不把它当成GPU帧时或所有设备的掉帧统计。真实浏览器上也出现短暂同步阶段connected=false，随后自动恢复；RTT仍可达约400–900ms，这部分未被本轮客户端CPU修复消除。

焦点测试按钮只临时加入本机HTML，已恢复原HTML并核对10个部署文件全部与WEB_RELEASE清单SHA一致；不会发布测试入口。公网静态部署 `4d207091-10e0-4101-af83-d8ea5143ec65` SUCCESS；权威服务仍为 `8b104ff7-7435-4e7c-83ea-5f8a2e307b5f` SUCCESS，未重新部署。首页200且完整内容与本地清单一致，PCK返回206、总长68477084，前65536字节与候选一致（这不是全PCK远端哈希）。Chrome实际打开该公开版本并进入纸间封面，图见public-release.png。

内置浏览器自动读取公开URL两次超时，未把它当作游戏或内置浏览器帧率证据，随后关闭该测试页并用Chrome核验。最终公网版的全局帧率没有另做物理设备采样；前后台及交互证据来自同包本地浏览器经公网WSS。临时焦点入口不在发布包内。测试浏览器窗口与本机预览进程均已关闭；测试时临时屏蔽的Chrome剪贴板权限已恢复为默认询问。

## 边界

没有用户设备的完整性能轨迹，不能保证所有设备恒定60fps。不同网络双电脑仍未实玩；本轮不迁移服务器地区、不改持久卷或权威模拟频率。

指标含义参考 [Godot Performance 官方文档](https://docs.godotengine.org/en/4.6/classes/class_performance.html)。
