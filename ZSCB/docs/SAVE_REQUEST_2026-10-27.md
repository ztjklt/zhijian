# 联机保存请求 · 2026-10-27

本轮把手动保存与保存后返回接入同一个客户端请求流程。原来未Ready时发送会直接返回-1，用户需要再次点击；旧成功回执也可能覆盖当前请求提示。没有修改服务器保存格式、权限、原子写入、物理、计费或协议10。SPEC v0.49，独立r16本地候选，公网仍r7／协议6。

## 行为

- 同步或短暂重连时先记录请求，未Ready不发送；最多等待10秒，重复点击合并。
- Ready后先重放旧的未确认操作，再发送新的save序号；只有服务器成功回执才报告保存成功。开始等待、发出、确认、失败及结果未知有文字提示。
- 发出后沿用3秒确认期限。断线或超时不自动重发，不清空草稿、图纸与场景；用户可显式重试。
- 请求绑定epoch／world。换世界、结束、主动离开或等待超时不会把旧请求延后发送到新世界。客人不能排队保存房主世界。
- 匹配迟到确认可以更新反馈，旧序号不能改写新请求提示。每张请求票据首次完成结果固定；超时后即使成功回执与返回协程同帧相遇，也不会自动返回。
- 保存后返回可加入已有手动保存，保存成功仍等leave成功。失败留在现场，可重试；原有单人保存流程不变。
- 网页房间菜单及作品菜单走同一当前请求；Web通知读取当前反馈。旧冻结客户端没有新能力时保留旧Ready保护与回执通知，不强行调用新API。

核心`net/save_request.gd`持有一次活动请求和最多8项完成结果，session负责Ready／回执／断线／世界替换接线，main实际保存入口调用session。没有新增持久化文件；现有个人资料仍走原保存流程。
